## 0. 手册导读

本手册按真实使用顺序写，不按技术模块写：

1. **初次使用**：启动客户端、登录小红书、配置任务、获客模型、安全拟人与承接规则。
2. **日常使用**：笔记生产与发布、自动浏览检索与评论、自动回复评论、自动回复私信。
3. **运行逻辑**：系统如何浏览笔记、如何基于设置与房源库匹配、如何生成评论/回复。
4. **管理视角**：管理浏览过的笔记、评论/回复内容、线索与未来 API 输出。

核心原则：

- **能配置的都不写死**：关键词、筛选、分类规则、话术、限频、排班、承接规则都应可配置。
- **先演练再真发**：默认演练；只有确认账号、话术、限频、合规都正常后才开真发。
- **不发明文联系方式**：评论、回复、私信都不出现明文微信、电话、二维码、外链。
- **房源与线索最终走 API**：未来房源由房源系统 API 输入，线索统一通过 API 输出到外部 CRM/企微/中台。

## 1. 产品全景

### 1.1 一句话

小红书自动化获客工具 = **一个桌面客户端驱动一个真实小红书账号**，按配置自动完成：

```
配置策略与房源
  → 生产并查看待发布笔记
  → 浏览检索笔记
  → 分层匹配
  → 浏览笔记
  → 生成评论/回复/私信
  → 限频真发
  → 收件承接
  → 联系方式识别
  → 线索沉淀与 API 输出
```

### 1.2 使用角色

| 角色 | 主要入口 | 关注点 |
|---|---|---|
| 中介运营 | 桌面客户端 | 账号登录、任务配置、启动/停止、查看运行日志、接手高意向线索 |
| 门店管理者 | 管理视角 / 中央后台（规划） | 每个账号跑了多少、回复了多少、产生多少线索、是否有风控异常 |
| 对接系统 | 房源 API / 线索 API（未来） | 输入可推房源图文；接收结构化线索与来源轨迹 |

## 2. 初次使用：配置与登录

### 2.1 启动客户端并登录小红书 `已实现`

**路径**：根目录双击 `启动小红书获客.command`，或命令行 `cd client && npm run app`

操作步骤：

1. 打开客户端，左侧进入「控制台」。
2. 若顶部提示未登录，点击「点我登录（弹出扫码）」。
3. 在右侧内嵌小红书浏览器中扫码或手动登录。
4. 回到控制台确认登录状态正常。
5. 先保持「真发（总开关）」关闭，完成演练。

注意事项：

- 登录发生在真实小红书页面中，系统不逆向接口，不保存小红书密码。
- 右侧浏览器可人工接管；系统动作也会显示红点轨迹。
- 未登录时真发会被拦截，不会假报发送成功。

### 2.2 任务设置：决定系统去哪里找人 `已实现`

**路径**：设置 › 任务设置

关键配置：

| 配置 | 作用 |
|---|---|
| 检索关键词 | 如「朝阳 租房」「望京 一居」，决定搜索入口 |
| 重新检索间隔 | 当前一批跑完后多久重新找新笔记 |
| 评论主方向 | 给评论生成使用，如“结合对方诉求，引导看主页/私聊，不留联系方式” |
| 排序 / 发布时间 / 笔记类型 / 搜索范围 | 通过小红书原生筛选面板拟人点击生效 |
| 排班 | 每个时段采集多少篇、最多评论多少条 |
| 时段内节奏 | 匀速摊开或开头集中 |

推荐初始配置：

- 新号：每天 1–3 条真评论，其他全部演练。
- 求租场景：排序用「最新」，发布时间用「一天内」或「一周内」。
- 搜索范围：优先「未看过」，降低重复触达。
- 每个时段同时配置「采集篇数」和「评论条数」，避免只采不发或过量发。

### 2.3 获客模型：决定什么内容值得处理 `已实现`

**路径**：设置 › 获客模型

> **重点：获客模型采用“规则 + 大模型”的混合判断。**
>
> 管理者不用把所有关键词写死，只要描述每个分类的判断口径。系统先用规则做边界和排除，再让大模型结合笔记标题、正文、图片一起分析，判断它属于哪类以及应该执行什么动作。

获客模型由五部分组成：

1. **分类定义**：例如「求租笔记」「高意向求租」「房源笔记」「中介/同行」「无关/不明」。
2. **判断描述**：用自然语言说明这个分类怎么看，而不是穷举所有关键词。
3. **混合判断**：规则负责边界、排除和兜底；大模型负责理解标题、正文、图片里的语义和上下文。
4. **动作定义**：每个分类命中后执行什么动作，可以配置为评论、回复、跳过、只记录、人工确认等。
5. **提取关键信息**：例如位置、预算、户型、入住时间、特殊要求，用于后续选房和生成话术。

#### 2.3.1 分类可以按管理诉求自定义

建议默认分类如下，实际可按城市、门店、行业或账号阶段调整：

| 建议分类 | 管理诉求 | 判断描述 | 建议动作 |
|---|---|---|---|
| **求租笔记** | 核心获客对象，优先处理 | 标题、正文或图片表达“正在找房、咨询租房、描述预算户型区域”等意图 | 评论 |
| **高意向求租** | 已经表达强需求或看房意愿 | 内容里已经出现明确预算、入住时间、想看房、想继续沟通等信号 | 评论后人工确认 / 线索观察 |
| **房源笔记** | 对方是在发房，不是客户 | 标题、正文或图片呈现房源发布、转租、招租、房间展示等内容 | 只记录或跳过 |
| **中介/同行** | 保护账号，避免同行互评 | 作者身份、文案风格或图片物料像房产营销、门店号、批量房源号 | 跳过并记录原因 |
| **无关/不明** | 判断不确定，避免误发 | 标题、正文、图片无法形成稳定判断，或分类之间存在冲突 | 人工确认或只记录 |

#### 2.3.2 分类判断使用规则 + 大模型

以「求租笔记」为例，不需要把所有词写完整，可以这样描述：

- **业务描述**：用户正在找房、求推荐、询问预算/区域/户型/入住时间。
- **规则边界**：明显发房、招租、同行营销、无关内容不要进入求租分类。
- **大模型判断**：结合标题、正文、图片一起看，判断对方到底是在找房、发房，还是只是无关讨论。
- **输出结果**：分类、把握程度、判断理由、提取到的关键信息、建议动作。

#### 2.3.3 每个分类可以配置动作

| 动作 | 适用对象 | 含义 | 管理建议 |
|---|---|---|---|
| **评论** | 求租笔记 / 高意向求租 | 生成评论草稿，过合规和限频后进入演练或真发 | 只给高价值分类开启 |
| **回复** | 评论承接 / 私信承接 | 对方已经互动后，按承接规则生成回复 | 与「评论承接」规则联动 |
| **跳过** | 同行、中介、无关、风险内容 | 不生成触达动作，只保留跳过原因 | 用于风控保护和降低无效触达 |
| **只记录** | 房源笔记、竞品样本、不确定内容 | 记录到采集/管理视角，不进入待评论 | 方便复盘分类质量和市场样本 |
| **人工确认** | 判断不确定、高价值、信息冲突 | 进入人工确认队列，再决定是否评论/回复/转线索 | 适合新规则上线初期 |

#### 2.3.4 提取关键信息，用于匹配房源和话术

```
对方笔记：「想找望京附近一居，预算 4500，最好近地铁」
  → 位置：望京
  → 户型：一居
  → 预算：4500
  → 关注点：近地铁
  → 房源库/API 选择：望京、一居、<=4500、地铁标签
  → 生成话术：回应望京+一居+地铁诉求，引导看主页/私聊
```

### 2.4 安全、模型与拟人：统一运行保护能力 `已实现`

**路径**：设置 › 安全与拟人 / 模型设置 / 防封控制

“模型与防封”和“防风控与拟人”表达的是同一套能力：让系统在真实浏览器里按真人路径运行，同时控制频率、合规红线和异常刹车。

可配置项：

| 配置 | 作用 |
|---|---|
| AI 文案服务商 | 火山方舟或阿里百炼，决定评论/回复草稿由谁生成 |
| 评论每日/每小时上限 | 控制真发数量，新号更保守，老号逐步放量 |
| 回复限频 | 控制评论回复、私信回复的每日、每小时和间隔 |
| 工作时间窗 | 让运行节奏更接近真实运营作息 |
| 承接范围 | 评论我笔记、回复我评论、@我、主动私信我的用户 |
| 安全红线 | 不发明文微信、电话、二维码、外链 |
| 异常刹车 | 未登录、验证码、风控提示、连续失败时立即停止 |

拟人技术方法：

| 方法 | 系统怎么做 | 用户能看到什么 |
|---|---|---|
| 贝塞尔鼠标轨迹 | 从上一次鼠标位置到目标点生成曲线，随机控制点，拆成多步移动 | 红点沿曲线移动，不是瞬间跳到按钮 |
| 鼠标轻微抖动 | 点击前后在目标中心附近做小范围偏移 | 点击位置不会每次完全一样 |
| 真实滚轮滚动 | 列表、正文、评论区用滚轮事件分段滚动，并加入停留时间 | 页面像真人一样一屏一屏看 |
| 逐字输入 | 评论和回复先定位输入框，再按字输入，字间隔有随机范围 | 演练时能看到内容逐字出现 |
| 随机阅读节奏 | 列表停留、看图停留、评论区停留、偶发长停顿都按范围随机 | 每轮运行节奏不同，不是固定频率 |
| 异常刹车 | 未登录、验证码、风控提示、发送失败率异常时停止真发 | 先保护账号，再提示人工处理 |

运行保护顺序：

```
真实浏览器
  → 真人路径
  → 拟人动作
  → 安全闸门
  → 异常刹车
  → 全程留痕
```

### 2.5 评论承接规则：决定如何回复别人 `已实现/增强中`

**路径**：设置 › 评论承接

配置项：

| 配置 | 作用 |
|---|---|
| 承接范围 | 评论我笔记、回复我评论、@我 |
| 意向关键词 | 命中后判为有意向 |
| 高意向词 | 如要联系方式、想私聊、想看房等 |
| 黑词 | 命中后跳过 |
| 只回复近 N 天 | 避免翻历史老评论 |
| 回复方向 | 生成回复的口吻与红线 |
| 回复限频 | 每日、每小时、间隔、一轮上限 |
| 默认演练 | 只定位和生成草稿，不真发 |

## 3. 日常使用流程

### 3.1 笔记生产与发布 `规划中`

本模块不是“直接自动发一篇笔记”，而是完整的房源内容生产、查看确认和发布流程。

目标：

- 先从房源库/API 里选择适合主推的亮点房源。
- 基于房源标题、位置、价格、户型、图片、卖点标签生成小红书笔记草稿。
- 草稿进入「待发布」清单，运营打开草稿就是在查看，可直接修改标题、正文、图片顺序和话题。
- 内容没问题后，只保留一个动作：点击「去发布」，发布后回填小红书笔记链接。
- 让后续评论/回复里说“看主页/私聊”时，主页真的有对应内容承接。

推荐流程：

1. **选择亮点房源**：从房源库或未来房源 API 选择今日主推房源，勾选封面、实拍图、卖点标签。
2. **生产笔记草稿**：系统生成标题、正文、话题标签、图片顺序和主卖点。
3. **进入待发布**：草稿生成后进入待发布清单。
4. **打开查看和修改**：运营打开草稿后检查图片、标题、正文，确认不含外链和明文联系方式。
5. **去发布并回填结果**：内容没问题就点击「去发布」，发布后记录小红书笔记链接、关联房源、发布时间和可承接标签。

HTML 可视化版用三张全页面图表达：

| 图 | 动作 |
|---|---|
| 图 3-1A | 选择亮点房源，生成笔记草稿 |
| 图 3-1B | 查看 AI 草稿预览，可改标题、正文、图片顺序和话题，确认后直接去发布 |
| 图 3-1C | 待发布清单，打开即查看；没问题就点「去发布」并回填链接 |

### 3.2 自动浏览检索与评论 `已实现`

**路径**：控制台 › 开始

主流程：

```
任务设置
  → 自动输入关键词进入搜索页
  → 自动设定排序 / 时间 / 类型 / 范围筛选
  → 自动浏览搜索结果页
  → 滚动采集候选笔记
  → 获客模型分类
  → 判断哪些笔记值得点开
  → 去重已评论笔记
  → 打开目标笔记
  → 切换图文图片 / 读正文 / 浏览评论区
  → 生成评论
  → 合规检查
  → 限频闸门
  → 演练定位或真发
  → 写入评论记录
```

运营怎么用：

1. 先在任务设置保存关键词、筛选、排班和评论方向。
2. 在控制台确认「真发（总开关）」关闭。
3. 点击「开始」，观察实时日志和红点轨迹。
4. 看待发送评论是否自然、是否命中对方诉求。
5. 小号、限频、话术都确认后，再打开真发。

自动浏览检索与评论的匹配依据：

- **用户设置**：关键词、筛选、排班、评论主方向、获客模型分类规则。
- **笔记内容**：标题、正文、标签、作者、互动数。
- **房源素材**：当前阶段主要通过话术方向承接；未来从房源库/API 选具体房源与配图。
- **安全规则**：不留联系方式、限频、排班、去重、登录检测。

自动采集和判断会形成两个结果：

| 结果 | 用户能看到什么 | 用途 |
|---|---|---|
| 采集记录 | 标题、作者、笔记链接、分类、赞评数、首次/最近采集时间 | 复盘机器看过哪些笔记 |
| 待评论记录 | 笔记分类、提取出的关键信息、生成评论、演练/真发状态 | 判断这条评论是否值得发 |

HTML 可视化版按“每个动作一张全页面系统图”展示，且统一基于当前客户端页面：左侧深色菜单、中间控制台/采集记录、右侧小红书页面。所有动作图都包含菜单栏；前 7 张是浏览检索和采集，第 8 张才进入评论内容判断：

| 图 | 动作 |
|---|---|
| 图 3-3 | 自动输入关键词搜索 |
| 图 3-4 | 自动设定筛选条件 |
| 图 3-5 | 自动浏览搜索页并采集候选笔记 |
| 图 3-6 | 自动判断哪个笔记值得点开看 |
| 图 3-7 | 自动切换图文笔记里的图片 |
| 图 3-8 | 自动浏览评论区 |
| 图 3-9 | 自动采集后进入采集记录列表 |
| 图 3-10 | 自动判断要评论什么内容 |

系统判断“值得点开”的主要依据：

- 分类动作为“评论”或“人工确认/复核”。
- 笔记不是已评论过的重复笔记。
- 没有命中同行、房源发布、黑词、无关内容等跳过条件。
- 标题、正文或图片中出现求租、预算、区域、户型、入住时间等有效信号。
- 在候选笔记里优先处理高意向、热度较高、诉求更明确的内容。

### 3.3 自动回复评论 `已实现/增强中`

**路径**：线索·承接 / 设置 › 评论承接

适用场景：

- 别人评论了我的笔记。
- 别人回复了我的评论。
- 别人 @ 我。

主流程：

```
控制台运行中
  → 定时检测页面底部消息入口的红色未读点
  → 有红点则暂停外呼
  → 点击底部消息入口
  → 进入通知页「评论和@」
  → 读取近 N 天互动
  → 去重入收件箱
  → 范围/黑词/意向词判断
  → 生成回复
  → 回复限频
  → 演练定位或真发
  → 更新收件箱状态
  → 高意向沉淀为线索
  → 回到主线继续外呼
```

回复策略：

- 高意向：对方想要联系方式、想看房、明确表达进一步沟通。
- 有意向：问价格、区域、地址、是否还有、整租/合租等。
- 其他：普通互动，可轻量回复或跳过。
- 黑词：同行、广告、无效内容跳过。

重点表现：

- 页面下方的红色未读点是触发入口，不是一直高频扫通知页。
- 检测到红点后先暂停外呼任务，再进入「评论和@」处理。
- 回复前仍要过承接范围、黑词、意向词、回复限频和合规红线。
- HTML 图使用当前控制台右侧的「评论和@」通知页，不再用独立后台表格表示。

### 3.4 自动回复私信 `规划中`

私信风险高于评论，产品上建议后置、克制启用。页面表达应接近小红书私信页：左侧是一列用户会话，右侧是当前用户聊天框。

未来流程：

1. 定时检测页面底部消息入口的红色未读点。
2. 有红点时点击消息入口，进入私信页。
3. 在左侧用户列表里识别未读会话，逐个进入右侧聊天框。
4. 读取对方最近对话，识别区域、预算、户型、入住时间、特殊要求。
5. 从房源库/API 选 1–3 套匹配房源。
6. 生成自然回复，可带房源图文；高风险内容先人工确认。
7. 多轮沟通中识别联系方式，命中高意向或复杂问题时转人工。
8. 写入线索并通过 API 输出。

页面重点：

- 底部红色未读点是私信承接触发入口。
- 私信页左侧展示一个个用户会话和未读点。
- 右侧聊天框展示上下文、系统回复草稿、提取到的需求和转人工动作。
- HTML 图使用当前控制台右侧的小红书消息页作为基底。

私信红线：

- 不主动发送明文微信、电话、二维码、外链。
- 不高频主动私信陌生人。
- 只在用户主动私信或强意向互动后承接。
- 识别到风控、验证码、登录异常立即停止。

## 4. 浏览、匹配、回复的核心逻辑

### 4.1 浏览笔记逻辑

系统不是只抓标题就评论，而是按“像真人浏览”的节奏执行：

1. 自动输入任务设置里的关键词，进入搜索结果页。
2. 自动应用用户配置的排序、发布时间、笔记类型、搜索范围。
3. 滚动列表，采集笔记卡片。
4. 移动鼠标到可见笔记卡片附近，模拟阅读。
5. 先用获客模型判断候选笔记是否值得点开。
6. 进入值得处理的详情页。
7. 根据配置自动切换图文笔记里的多张图片。
8. 正文停留一段随机时间。
9. 向下翻评论，观察评论区。
10. 关闭详情页，回到列表。

浏览过程会同步采集和判断：

| 自动动作 | 系统怎么做 | 产出 |
|---|---|---|
| 自动输入关键词 | 读取任务设置里的关键词，进入小红书搜索页 | 本轮来源关键词 |
| 自动设定筛选 | 点选排序、发布时间、笔记类型、搜索范围 | 筛选生效日志，后续可复盘筛选上下文 |
| 自动浏览搜索页 | 滚动结果列表，鼠标移动到可见笔记卡片附近 | 候选笔记列表 |
| 判断是否点开 | 用获客模型给候选笔记分类，并结合去重、热度和动作排序 | 待浏览目标、跳过原因 |
| 浏览图文详情 | 切换图片、读正文、浏览评论区 | 正文、标签、评论区片段等生成依据 |

浏览参数来自任务设置 / 防封配置：

- 每时段采集篇数。
- 图文看几张图。
- 正文停留时长。
- 评论区滚动次数。
- 每次滚动后的停留时间。
- 工作时段、限频、养号阶梯。

### 4.2 匹配逻辑：设置 + 房源库/API

完整匹配分四层：

| 层级 | 判断内容 | 作用 |
|---|---|---|
| L1 硬过滤 | 城市、商圈、时间窗 | 不符合直接淘汰 |
| L2 意向 | 求租 / 房源 / 同行 / 不明 | 决定评论、跳过、记录或复核 |
| L3 结构化诉求 | 预算、户型、入住时间 | 用于筛选可推荐房源 |
| L4 语义诉求 | 近地铁、可养宠、采光、短租等 | 用于选卖点和生成话术 |

未来房源 API 输入后，系统会把对方诉求映射到房源：

```
对方诉求
  区域=望京
  预算<=4500
  户型=一居
  标签=近地铁

房源 API 返回
  房源 A：望京 / 一居 / 4300 / 近地铁 / 3 张图
  房源 B：望京 / 开间 / 3900 / 可短租 / 4 张图

匹配输出
  首推 A
  回复重点：区域、预算、近地铁
  图片：优先封面 + 地铁卖点图
```

### 4.3 评论生成逻辑

评论生成输入：

- 对方笔记标题、正文、标签。
- 获客模型分类结果与证据。
- 图文笔记里的图片信息。
- 评论区片段。
- 提取出的关键信息：位置、预算、户型、入住时间、关注点。
- 评论主方向。
- 房源匹配结果（未来）。
- 合规红线。

评论判断分两层：

| 判断层 | 看什么 | 输出 |
|---|---|---|
| 能不能评论 | 笔记分类动作、是否已评论、是否命中同行/房源/黑词、账号限频、是否已登录 | 评论 / 跳过 / 只记录 / 人工确认 |
| 评论什么内容 | 位置、预算、户型、入住时间、近地铁/通勤/可养宠等关注点，以及评论主方向 | 一句具体回应，不泛泛打招呼 |

生成后必须检查：

- 是否超过长度。
- 是否包含明文联系方式。
- 是否包含外链或二维码表达。
- 是否明显重复、机械。
- 是否与对方诉求有关。

### 4.4 回复生成逻辑

回复生成输入：

- 对方评论/回复内容。
- 承接范围。
- 意向关键词、高意向词、黑词。
- 回复方向。
- 历史是否已回复。
- 回复限频与一轮上限。

回复状态：

| 状态 | 含义 |
|---|---|
| 待处理 | 已入库，尚未回复 |
| 已回复 | 已真发并确认 |
| 跳过 | 命中黑词、无正文、超出时间窗、重复等 |
| 失败 | 定位失败、发送失败、未确认成功 |
| 演练 | 生成草稿或定位成功，但未真发 |

### 4.5 安全与拟人能力

该能力已并入 2.4「安全、模型与拟人」，避免“模型与防封”和“防风控与拟人”重复表达。核心逻辑仍然是：真实浏览器、真人路径、拟人动作、安全闸门、异常刹车、全程留痕。

## 6. 未来 API 对接

### 6.1 房源 API 输入

目标：房源不再靠本地手动录入，而是从公司房源系统获取最新房源图文。

房源 API 至少需要提供：

| 字段 | 示例 |
|---|---|
| 房源 ID | `house_001` |
| 城市 / 商圈 / 小区 | 成都 / 天府三街 / 某小区 |
| 价格 | 3200 |
| 户型 | 一居 |
| 租赁方式 | 整租 / 合租 |
| 卖点标签 | 近地铁、押一付一、可养宠 |
| 图片列表 | 封面、卧室、客厅、地铁距离图 |
| 可用状态 | 可推 / 已租 / 暂停 |
| 更新时间 | 用于避免推荐过期房源 |

### 6.2 线索 API 输出

目标：客户端本地识别线索后，统一推送给外部 API。

输出时机：

- 识别到对方联系方式。
- 对方明确约看房或问具体房源。
- 运营手动标记为高意向。
- 私信多轮对话达到转人工阈值。

建议输出内容：

```
线索基础信息
  小红书昵称 / 主页链接 / 来源账号

来源上下文
  来源笔记 / 来源评论 / 对话摘要 / 原始链接

需求结构化
  城市 / 区域 / 预算 / 户型 / 入住时间 / 特殊要求

转化信息
  联系方式 / 意向等级 / 跟进状态 / 推荐房源

系统字段
  tenant_id / client_id / lead_id / created_at / push_status
```

失败处理：

- 断网不丢，本地保留待重试。
- 外部 API 返回失败时记录失败原因。
- 支持手动重推。
- 同一用户/同一联系方式要去重。

## 7. 验收清单

### 初次使用

- 能打开客户端并完成小红书登录。
- 未登录时真发被拦截。
- 任务设置保存后，控制台开始即使用新配置。
- 排班、采集篇数、评论配额能生效。
- 安全、模型与拟人配置可保存，真发前能走限频、合规、拟人动作和异常刹车。

### 日常使用

- 笔记生产与发布能表达“选亮点房源 → 生成草稿 → 打开查看/修改 → 去发布”的目标流程。
- 自动浏览检索与评论能完成检索、筛选、浏览、采集、分类、点开详情、生成、合规、发送/演练、记录。
- 自动回复评论能定时检测底部红色未读点，进入评论和 @，入库、去重、判意向、生成回复、更新状态。
- 自动回复私信能表达底部红点触发、左侧用户列表、右侧聊天框、需求识别和转人工。

### 管理视角

- 采集记录可看浏览过的笔记。
- 评论记录可看已发内容和状态。
- 收件箱可看用户互动、回复草稿、回复状态、失败原因。
- 线索能追溯来源，并预留 API 输出状态。

### 安全与合规

- 评论/回复/私信不发明文联系方式、二维码、外链。
- 真发受每日、每小时、最小间隔、排班、养号阶梯共同约束。
- 发现登录异常、验证码、连续失败时能停止或提示人工介入。
- 房源 API 和线索 API 都要有失败重试与本地留痕。
