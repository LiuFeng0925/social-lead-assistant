## 0 一句话

第一期 = 把全链路里**最有价值、风险可控**的一段竖切——「**检索 → 匹配 → 生成评论(话术+房源配图) → 自动评论 → 记录**」——在**单账号**上端到端跑通。**只到「评论」为止**;私信、多轮自动沟通、加微转化是第二期。

---

## 1 为什么第一期先做"评论闭环"

| 理由 | 说明 |
|---|---|
| **风险最低、需求已排期** | 需求 4.4 把四类触达按风险排期:自动评论笔记(`FR-4.1`)、回他人评论区(`FR-4.2`)= 中风险"先做";主动私信(`FR-4.4`)= 最高风险"最后做"。第一期只取"先做"的两个。 |
| **能独立产生价值** | 在求租帖下评论自家房源、在评论区回"问房子"的人——这本就是中介现在**人工在做的核心动作**,自动化后立即有产出。 |
| **把地基串一遍** | 接管浏览器 → 检索 → 匹配 → 内容生成 → 发评论 → 防封 → 落库,整条链路全走通。第二期加私信/加微,只是在这条链上**接楼层**,不返工。 |
| **不碰最高危动作** | 不做"主动私信陌生人"(风控最狠),第一期存活概率最高,适合拿测试小号先跑。 |

## 3 端到端流程(本期 5 步)

```
①检索 ──→ ②匹配 ──→ ③生成 ──→ ④自动评论 ──→ ⑤记录&监控
关键词×城市   地区时间      LLM话术       笔记下评论        评论结果
搜笔记/评论    →意向          +房源配图      +回评论区问房者     +潜客标记
去重入队      →诉求(轻)       +合规过滤      (限频/拟人/可刹车)   (实时流水)
```

全程受**防封号与运行控制**约束(限频、工作时间窗、随机节奏、健康监控、紧急刹车)。

## 4 关键界面(高保真见 HTML 版)

第一期客户端用"左侧模块导航 + 主区"。本期高保真重点画 **4 个运行闭环界面**,配置类页面给要点。

| # | 界面 | 作用 | 关键元素 | 验收点 |
|---|---|---|---|---|
| 1 | **控制台** | 一眼看清账号状态、今日产出、一键启停/刹车 | 启停总开关、今日数据卡(评论数/命中/潜客/健康分)、当前运行阶段、紧急刹车、账号健康 | 启停即时生效;刹车一键停所有动作 |
| 2 | **运行监控(实时闭环)** | 看机器此刻在干什么 | 全链路流水、当前处理的笔记卡、实时日志、本轮统计、**监控器(真实 Chrome 实时可见·可手动接管 + 客户端快照)** | 每步状态可见;限流高亮;真窗口可手动接管;出错留快照 |
| 3 | **内容生成工作台** | 第一期:你给一个评论主方向,AI 逐条生成 | **评论主方向输入** + 配图选择 + AI 为某条笔记生成的预览 + **合规红线检查** | 评论按方向逐条生成、不雷同;带匹配房图;合规器拦截明文联系方式 |
| 4 | **评论记录与潜客** | 沉淀本期成果 | 评论**详细记录**(时间/原笔记+作者/**可跳转链接**/全文/配图/状态/失败原因)+ 单条详情 + 潜客列表 | 每条可查可跳转原笔记;失败原因留痕;潜客可标记 |

**配置类页面(要点,沿用统一功能卡):** 检索(已有样板 2.2)、匹配规则(四层开关+阈值,本期 L1/L2 必填)、话术库(风格/模板/暗语自填)、房源素材库(结构化录入+标签映射)。

## 5 第一期验收标准(跑通的标志)

**端到端**:配置好策略与素材 → 控制台一键启动 → 系统在限频与拟人节奏下自动检索到匹配笔记 → 生成合规评论+配图 → 发出 → 记录可见 → 账号不被封。

逐条:

1. 能**接管已登录的 Chrome** 并确认账号在线(不需重新登录)。
2. 检索能按"关键词×城市"拿到候选笔记 + 评论区,去重入队。
3. 匹配能**淘汰**不符地区/时间的笔记,能**区分**求租/房源走不同评论方向。
4. 评论**由用户给定一个"主方向",LLM 按每条笔记逐条生成个性化、不雷同的评论**(规避复制粘贴刷屏),附按诉求匹配的房源图,且**不含明文微信/电话/二维码/外链**(合规器拦截违规内容)。
5. 评论在**每日上限 + 随机节奏**下发出;**紧急刹车**能即时停止所有动作;运行中可在**被接管的真实 Chrome 窗口**直接看到操作并随时手动接管,客户端内也有截图快照与出错留痕。
6. 评论结果**详细记录**(时间/原笔记标题+作者/**可跳转链接**/评论全文/配图/状态/失败原因),评论区"问房者"潜客被标记入库。
7. 出现限流/异常信号能**自动降速或暂停**并在界面提示(不静默失败)。

> 量化指标(连续运行 N 天不封、每日评论 X 条、命中率)待测试小号试跑后按运营基线设定(需求 11 章 / Q9)。
