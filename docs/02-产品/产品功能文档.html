2.2任务设置:检索条件 + 筛选 P0 ✅已实现

↓ 「任务设置」页 = 整体条件(关键词/筛选/评论方向/抓取上限)+ 排班(见 2.10);本节讲整体条件。

功能卡 · 任务设置:检索条件 + 筛选
功能目的让运营自定义检索条件,系统据此在小红书上找到相关求租/房源笔记及其评论区,作为后续匹配与触达的来源。
用户怎么用在「任务设置」页配置:搜索关键词、筛选(排序/发布时间/笔记类型/搜索范围,= 小红书搜索页原生筛选)、评论主方向、抓取上限 → 点"保存";控制台「▶ 开始」即按保存的设置跑。
详细规则 ① 用关键词生成检索词进搜索页;
② 筛选用拟人点击应用——不在 URL 拼参数,而是导航后像真人一样点开筛选面板、按可见文字("最新""一周内""图文"等)点选(排序若是下拉先展开),按文字定位、抗改版,命中/未命中都打日志;
③ 读取每条笔记:标题/正文/标签/发布时间/作者/地区,以及评论区(识别"问房子"潜客);
④ 受全局限频与拟人节奏约束(翻页随机间隔 + trusted 滚轮);
⑤ 采集进匹配漏斗(见 2.3);⑥ 已处理去重,不重复触达。

2.10排班管理 P0 ✅已实现

排班决定 WHEN(什么时候开工、每段跑多少),防封决定 HOW FAST/SAFE,两者叠加取最严。参考同机 BOSS「Agent 工作时间」并简化适配(单账号、单一评论动作)。

功能卡 · 排班管理
功能目的按"周几 + 时段"安排机器作息,并给每段单独设评论条数上限,贴近真人节律、分散行为、降低风控风险。
用户怎么用「任务设置」页下半「排班」区:① 开/关启用排班;② 周一~周日每天 开关上班 + 设工作时段(可多段);③ 每段填评论条数上限;④ 选时段内节奏;⑤ 保存。
详细规则 ① 只在"今天周几"对应、且命中当前时刻的时段内才动作,非时段/休息日自动收工;
② 每段配额 = 该时段最多发多少条,发够即停、等下段;
③ 节奏:匀速摊开按"时段已过百分比"放行,开头集中配额内连续放行;
④ 养号阶梯/每日上限是安全天花板,任何配额都突破不了;每小时上限、最小间隔照常叠加(取最严);
⑤ 启用排班后优先于「防封控制」的单一工作时段(后者作兜底)。
配置项
配置项默认取值/说明
启用排班开关=不限时段,只受防封限频约束
每天 上班开关全开周一~周日各一个;关=该天休息
工作时段09:30–23:00每天可多段;时:分
每段评论上限8该时段最多发多少条评论
时段内节奏匀速摊开匀速摊开 / 开头集中发完再歇
冲突校验同一天多个时段不得重叠、开始须早于结束(首尾相接合法);保存时拦截并提示哪天哪两段;编辑时实时标红冲突段。
异常与边界全天休息→当天不动作;配额留空→默认 8;旧数据无 quota→该段不设时段配额、仅受养号天花板。
优先级P0
关联需求FR-9.2/9.3/9.4 · 反检测清单第 2 类
验收标准
  • 设某天休息,该天到点不动作;限频原因显示"今天(周X)排班为休息日"。
  • 某天设两段不同配额,各段发够即停、互不挪用。
  • 匀速节奏下时段刚开始不会一次发完配额;开头集中配额内连续放行。
  • 新号即使把配额配高,实发也不超过养号阶梯当天上限(如第 1 天 3 条)。
  • 同日时段重叠或起止颠倒:保存被拦并提示;编辑时冲突段实时红框。

2.12运行监控与日志 P1 ◐部分已实现

功能卡 · 运行监控与日志
功能目的让运营实时看到机器在浏览器里的真实操作(画面 + 鼠标轨迹),建立信任、便于发现异常。
用户怎么用控制台「实时监控」区:看内嵌浏览器实时画面 + 明显的红点光标,跟随机器鼠标移动/滚动/点击;下方实时日志逐行打印引擎动作。
详细规则 ① 画面用 CDP 截图流(screencast)实时推送;
② 红点=机器鼠标位置:移动按贝塞尔轨迹、滚动随页翻动、点击放扩散环,走过留淡出彗星尾巴画出路径;
③ 监控画面一连上,红点居中常驻显示(呼吸脉动)便于辨认;
④ 画面可点击 = 直接在监控里操作内嵌浏览器;坐标按画面缩放比映射。
异常与边界监控画面未连上(无截图帧)时红点不显示——属预期,连上即居中出现。
优先级P1
关联需求FR-C · 反检测清单第 6 类
验收标准
  • 跑检索时,红点沿轨迹移动、滚动翻页拖尾巴、点开笔记放扩散环。
  • 红点足够明显(约 42px + 红心白环红晕 + 脉动),白底页面清晰可见。
  • 在监控画面上点击能驱动内嵌浏览器。

2.13评论承接:收件箱 + 自动回复 P0 ○待实现

承接 = 接住回头客。别人评论我笔记 / 回复我留言 / @我 → 自动接住、按意向回复、沉淀线索。承接回复优先级高于主动评论:任务运行中随时发现有通知,先回复再回外呼。
功能卡 · 评论承接
功能目的补上获客闭环后半段:接住已经在跟你互动的人(意向远高于冷启动),自动回复并沉淀为线索。
用户怎么用与主动评论同一个「开始」:引擎边外呼边盯通知,发现「评论和@」有新内容就暂停外呼、进通知页逐条回复、再回外呼。内容/状态在「线索·承接」页看,规则在「评论承接」设置页配。
详细规则 ① 抢占式单循环:每个安全断点(评完/关掉一篇笔记、回到列表)先读底部「通知」红点(纯读 DOM、不动鼠标、零打扰);有未读 → 暂停外呼 → 进通知页 → 抓「评论和@」→ 逐条判意向+回复 → 回搜索页;
② 检查只"看"不点,确有未读才点进去;
③ 回复永远第一优先级,外呼填空闲;不掐在输入/发送中间,只在断点切换;
④ 回复走 JS 合成事件 + 红点慢动作可见;一轮最多回 M 条就还控制权给外呼(防饿死);
⑤ 红线:回复不留明文微信/电话/二维码/外链,一律"看主页/私聊"。
输入 / 输出输入:通知页「评论和@」条目(昵称/内容/笔记/动作/日期/主页链接)。输出:自动回复 + inbox 记录 + 高意向线索。
异常与边界笔记详情页底栏不在 → 放到"回到列表"断点读红点,读不到则每 N 分钟轻进通知页看一眼;回复没定位到框/发送没确认 → 标 failed、不算已回、可重试(有上限);连续失败/登录掉线/风控提示 → 安全刹车自动停。
优先级P0
关联需求承接/转化 · 反检测清单第 4 类(安全刹车) · 私信一期方案
执行策略(抢占循环) 
任务开始 → 循环:
  ① 该停吗?(停止 / 安全刹车 / 不在排班时段) → 是则结束
  ② 看通知红点(读 DOM,不动鼠标)
       有未读 → 暂停外呼 → 进通知页 → 抓「评论和@」
              → 逐条:判意向 → 命中规则才回 → 生成回复 → 限频闸门 → 回复(演练/真发) → 记录
              → 一轮≤M条 → 回搜索页
  ③ 没未读 / 已处理完 → 外呼走一步(下一篇求租帖 → 浏览 → 评论)
  ④ 回到 ①
单浏览器 = 单循环抢占(非两个真并行线程);回复随时插队,处理完靠去重恢复外呼上下文。
配置项(「评论承接」设置页,全部可配)
  • 承接范围:回我评论✓ / 评我笔记✓ / 赞收藏✗ / 关注✗(可开自动回关)
  • 意向关键词(命中才回)· 黑名单/黑词(命中跳过,已回不重复)
  • 只回复近 N 天(默认 7,0=不限):只接近 N 天的评论,抓取滚到更老就停,不用全读
  • 回复话术:分意向多套轮换,模板/AI 切换,红线不留联系方式
  • 回复限频:日上限/每小时/最小间隔(共用或单独 reply_*)· 一轮上限 M(默认 5)
  • 检查通知频率(每篇+兜底 N 分钟)· 真发开关(默认演练,真发二次确认)
结果记录
  • inbox 收件箱:昵称/主页/内容/笔记/动作/意向/状态(待处理·已回复·跳过·失败·演练)/回复内容/失败原因/时间
  • 统计:今日收到·已回·跳过·失败·高意向·回复成功率(喂安全刹车)
  • 线索沉淀(leads 扩展):高意向→昵称/主页/最近诉求/跟进状态(待跟进·已加微·转人工·无效),可看完整往来
验收标准
  • 运行中制造一条新评论通知 → 引擎下一个断点"看"到红点 → 暂停外呼 → 进通知页回复 → 回外呼。
  • 检查通知不移动鼠标、不打断外呼(纯读 DOM)。
  • 回复按意向、不雷同、无明文联系方式;「线索·承接」页能看到收件+状态+回复;高意向进线索。
  • 演练只生成不发;真发受限频 + 安全刹车。
分步实现(边做边改)
