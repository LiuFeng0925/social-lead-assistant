1产品定位与组成

一句话:一个"每账号一个桌面客户端 + 一个中央汇总后台"的小红书全自动获客系统,客户端驱动用户真实浏览器,在小红书上自动完成"检索→匹配→评论/私信→引导加微→线索沉淀"。

产品由三大块组成:

  • 外部依赖 — 小红书网页版(操作对象)、用户真实 Chrome(用 CDP 驱动)、国产大模型(智能来源)。
  • 桌面客户端(本期重点) — 产品主体,内部按四层组织。
  • 中央后台(薄层) — 汇总所有账号的状态与线索,跨账号观测。

关键洞察 执行引擎是产品的"心脏",配置层喂它、智能&驱动支撑它、保障&数据守护它并存住成果。后面每个功能模块,都能在这张图上找到自己的位置。

3四层职责详解

层职责包含什么 / 关键点
配置层把"做什么、怎么做"交给用户配,不写死检索条件、匹配规则与阈值、话术风格与配图规则、房源库、话术库、限频与工作时间。原则:能配置的都不写死。
执行引擎
(核心)		把配置变成实际获客动作的主链路检索 → 匹配漏斗(地区时间/意向/预算户型/诉求) → 内容生成(话术+选房配图) → 触达(评论/主动私信/回评论区) → 自动多轮沟通 → 加微转化(诱导/识别入库/转人工)。
智能&驱动提供"理解力"与"操作小红书的手"LLM:匹配精筛、话术生成、对话意向分级、微信号识别(可切换国产 provider)。浏览器:CDP 驱动真实 Chrome、isTrusted 拟人输入、反检测、页面选择器适配。
保障&数据让全自动"活得久"并留住成果限频、养号阶梯、工作时间窗、账号健康监控、紧急刹车、任务调度;本地 SQLite 存笔记/线索/对话/状态/配置(断网不丢)。
中央后台跨账号观测与线索归集(薄层)Token 鉴权接入、账号状态看板、线索归集、运营总览;多租户与外部对接预留。只观测、不下指令。

6技术栈(概要)

客户端Electron + 本地 Node 服务 + 本地 SQLite;CDP(Chrome DevTools Protocol)驱动真实 Chrome;复用 BOSS 寻源助手资产
智能国产大模型(火山 Ark / 阿里百炼),可切换 provider
后台云服务器 + Token 鉴权;多租户数据库(建议 PostgreSQL,带 tenant_id)
反爬策略驱动真实浏览器,由页面自身生成 x-s 签名,绕过签名墙(不逆向 API)
