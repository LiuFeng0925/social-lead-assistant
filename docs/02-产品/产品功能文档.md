## 1 产品总览

### 1.1 角色与使用场景

| 角色 | 用什么 | 典型场景 |
|---|---|---|
| 中介运营 | 桌面客户端（1 人 1 账号） | 配置城市/关键词/匹配/话术/房源 → 一键启动 → 机器自动获客 → 收到"转人工"提醒时接手 → 查看本账号线索 |
| 管理者 | 中央后台（网页） | 看所有账号今天跑得怎么样、有没有被限流、共产出多少线索；汇总导出线索 |

### 1.2 信息架构 / 页面地图

**桌面客户端**（左侧导航；已实现部分按当前客户端对齐）：
- **控制台** — 只做监控：登录状态、实时监控器（内嵌浏览器画面 + 机器鼠标轨迹红点）、阶段进度、指标、实时日志、**开始/停止**、待发评论复核。**不放任何配置**。
- **设置** 分组：
  - **任务设置** — 检索关键词 + 筛选（排序/发布时间/笔记类型/搜索范围）+ 评论方向 + 抓取上限；并入「排班」(见 2.10)
  - **排班管理** — 按周几多时段 + 每段评论配额 + 时段节奏
  - **防封控制** — 限频、养号阶梯、配额浮动、紧急刹车
  - **评论承接**（待实现）— 承接范围、意向词、黑词、回复话术、回复限频、真发开关（见 2.13）
- **记录** 分组：**评论记录** · **采集记录** · **线索·承接**（待实现：收件箱 + 高意向线索）
- （规划中）**匹配规则** · **内容生成** · **房源素材库** · **话术库** · **触达执行** · **线索** · **配置中心** · **账号/接入设置**

> 注：信息架构已从"每个功能页自带配置+启停"重构为"**控制台只监控/启停，配置类统一收进设置分组**"——比早期草案更干净，也是当前客户端的实际形态。

**中央后台**（网页）：账号总览看板 · 线索汇总 · [P2] 租户管理

### 1.3 端到端使用流程

1. **接入** — 安装客户端 → 启动/连接已登录小红书的 Chrome → 绑定账号
2. **配置** — 设目标城市（可多城）+ 关键词 + 匹配条件 + 话术库 + 房源库 + 限频/工作时间
3. **启动** — 控制台一键启动；系统在限频与拟人节奏下自动运行
4. **自动获客** — 检索 → 分层匹配 → 生成话术+配图 → 评论/私信触达
5. **沟通转化** — 对方回复→自动多轮沟通、诱导加微；识别对方微信入库
6. **转人工** — 高意向/复杂对话→标记并提醒运营接手
7. **沉淀** — 线索本地保留 + 上报后台；管理者在后台统一观测

## 2.2 任务设置：检索条件 + 筛选 `[P0]` ✅已实现

> 「任务设置」页 = 整体条件（关键词 / 筛选 / 评论方向 / 抓取上限，全局一套）+ 排班（见 2.10）。本节讲整体条件；排班单列。界面 mockup 见 HTML 版。

### 功能卡

| 字段 | 内容 |
|---|---|
| **功能目的** | 让运营自定义检索条件，系统据此在小红书上找到相关求租/房源笔记及其评论区，作为后续匹配与触达的来源。 |
| **用户怎么用** | 在「任务设置」页配置：搜索关键词、**筛选**（排序 / 发布时间 / 笔记类型 / 搜索范围，= 小红书搜索页原生筛选）、评论主方向、抓取上限 → 点"保存"；控制台「▶ 开始」即按保存的设置跑（无参数时后端读 config 默认）。 |
| **详细规则** | ① 用关键词生成检索词进搜索页；② **筛选用拟人点击应用**——不在 URL 拼参数，而是导航后像真人一样在页面上点开筛选面板、按可见文字（"最新""一周内""图文"等）点选对应项（排序若是下拉先展开）；按文字定位、抗改版，命中/未命中都打日志；③ 读取每条笔记：标题/正文/标签/发布时间/作者/地区，以及评论区（识别"问房子"潜客）；④ 受全局限频与拟人节奏约束（翻页随机间隔 + trusted 滚轮）；⑤ 采集结果进匹配漏斗（见 2.3）；⑥ 已处理笔记/评论去重，不重复触达。 |
| **输入 / 输出** | 输入：检索配置。输出：候选笔记/评论列表（含元数据），写入本地待匹配队列。 |
| **异常与边界** | 搜索无结果→提示并跳过；页面改版/选择器失效→记录错误并告警（不静默失败）；触发限流→自动降速/暂停并上报；重复内容→去重跳过。 |
| **优先级** | P0 |
| **关联需求** | `FR-1.1~1.4` · `FR-C.1` · 需求 `4.2 L1` |

### 配置项

| 配置项 | 默认 | 取值/说明 |
|---|---|---|
| 地区匹配开关 | 开 | 关闭则不限城市 |
| 目标城市 | 空 | 可多城；**不绑账号属地**（人在 A 城业务在 B 城） |
| 搜索关键词 | 空 | 多个，逗号/换行分隔 |
| 笔记类型 | 求租+房源 | 求租帖 / 房源帖 可分别勾选 |
| 时间窗 | 无预设 | N 天内；求租按发帖、评论客户按评论时间 |
| 采集范围 | — | 每次最多 N 条、翻页深度 N 页 |
| **排序方式** | 综合 | 小红书原生：综合 / 最新 / 最多点赞 / 最多评论 / 最多收藏（求租帖建议「最新」抓刚发的） |
| **发布时间** | 不限 | 小红书原生：不限 / 一天内 / 一周内 / 半年内（配「最新」只触达近期求租） |
| **笔记内容形式** | 不限 | 小红书原生：不限 / 图文 / 视频（与上面"笔记类型=求租/房源"的意向分层是两回事） |
| **搜索范围** | 不限 | 小红书原生：不限 / 已看过 / 未看过 / 已关注（用"未看过"天然避重复触达） |
| **评论主方向** | — | 喂给生成的口吻/立场（如"房源方友好回应、引导看主页、不留联系方式"） |
| **抓取上限** | 40 | 每轮检索最多采集多少条笔记 |

### 验收标准

- 配置 ≥2 个目标城市 + 多个关键词后，系统能按"关键词×城市"逐组检索并返回候选笔记。
- 关闭"地区匹配"后，检索不再受城市限制。
- 采集到的每条笔记都带：标题、正文、标签、发布时间、作者、地区、评论。
- 同一笔记/评论不会被重复采集进待处理队列。
- 翻页/采集间隔存在随机抖动，非固定节奏。
- 页面结构异常时有明确错误提示与日志，不静默丢数据。
- 选「排序=最新 / 发布时间=一周内 / 内容形式=图文 / 搜索范围=未看过」后，系统在搜索页**以拟人点击**应用这些筛选，结果随之变化；某筛选项文字未命中时日志明确提示、不静默。
- 任务设置保存后，控制台「开始」即按保存值运行（含筛选）。

### 界面要点（mockup 见 HTML 版）

- 「任务设置」页（设置分组下）：上半「整体条件」= 关键词 + 抓取上限 + 评论方向 + 4 个筛选下拉（排序/发布时间/笔记类型/搜索范围）；下半「排班」见 2.10；底部 [保存任务设置 + 排班]。
- 控制台「本次运行」：开始/停止 + 任务摘要（关键词·排序·时间·类型）+ 进度条 + 命中计数 + 候选笔记表 + 待发评论复核。

## 2.10 排班管理 `[P0]` ✅已实现

> 把"什么时候开工、每个时段跑多少"做成可配置。**排班决定 WHEN，防封决定 HOW FAST/SAFE**，两者叠加取最严。参考同机 BOSS 项目的「Agent 工作时间（按周几多时段）」做法并简化适配（单账号、单一评论动作）。

### 功能卡

| 字段 | 内容 |
|---|---|
| **功能目的** | 让运营按"周几 + 时段"安排机器作息，并给每个时段单独设评论条数上限，贴近真人节律、分散行为、降低风控风险。 |
| **用户怎么用** | 「任务设置」页下半「排班」区：① 开/关「启用排班」；② 周一~周日每天 开关「上班」+ 设工作时段（可多段，如 09:30–12:00 / 14:00–23:00）；③ 每段填「评论条数上限」；④ 选「时段内节奏」；⑤ 保存。 |
| **详细规则** | ① 只在"今天周几"对应、且命中当前时刻的时段内才动作；非时段/休息日自动收工。② 每段配额 = 该时段最多发多少条评论，发够即停、等下个时段。③ 节奏：**匀速摊开**=按"时段已过百分比"放行（进度到一半才让发到一半）；**开头集中**=配额内直接连续放行。④ **养号阶梯/每日上限是安全天花板**，任何配额都突破不了；每小时上限、最小间隔照常叠加（取最严）。⑤ 启用排班后**优先于**「防封控制」的单一工作时段（后者作未启用排班时的兜底）。 |
| **输入 / 输出** | 输入：7 天排班（每天 `on` + 多时段 `[{start,end,quota}]`）+ 节奏 `slot_pacing`。输出：运行期"现在能不能发"的判定依据。 |
| **冲突校验** | 同一天多个时段**不得重叠**、开始须早于结束（首尾相接如 12:00 接 12:00 视为合法）；**保存时拦截**并提示哪天哪两段冲突；**编辑时实时标红**冲突/非法时段并悬浮原因。 |
| **异常与边界** | 全天休息→当天不动作；配额留空→默认 8 条；旧数据无 `quota`→该段不设时段配额、仅受养号天花板。 |
| **优先级** | P0 |
| **关联需求** | `FR-9.2 / 9.3 / 9.4`（限频/节奏/养号）· 反检测清单第 2 类 |

### 配置项

| 配置项 | 默认 | 取值/说明 |
|---|---|---|
| 启用排班 | 开 | 关 = 不限时段，只受防封限频约束 |
| 每天 上班开关 | 全开 | 周一~周日各一个；关 = 该天休息 |
| 工作时段 | 09:30–23:00 | 每天可多段；时:分 |
| 每段评论上限 | 8 | 该时段最多发多少条评论 |
| 时段内节奏 | 匀速摊开 | 匀速摊开 / 开头集中发完再歇 |

### 验收标准

- 设某天休息，该天到点不动作；限频原因显示"今天（周X）排班为休息日"。
- 某天设两段（上午/下午）不同配额，各段发够即停、互不挪用。
- 匀速节奏下时段刚开始不会一次发完配额；开头集中节奏下配额内连续放行。
- 新号即使把配额配高，实发也不超过养号阶梯当天上限（如第 1 天 3 条）。
- 同日时段重叠或起止颠倒：保存被拦并提示；编辑时冲突段实时红框。

### 界面要点（mockup 见 HTML 版）

- 「任务设置」页下半：启用排班开关 + 时段内节奏下拉 + 周一~周日 7 行（上班勾选 + 多个「开始–结束 + N 条」+ 加/删时段）。
- 冲突时段红框 + 悬浮原因；底部「保存任务设置 + 排班」。

## 2.12 运行监控与日志 `[P1]` ◐部分已实现

### 功能卡

| 字段 | 内容 |
|---|---|
| **功能目的** | 让运营实时看到机器在浏览器里的真实操作（画面 + 鼠标轨迹），建立信任、便于发现异常。 |
| **用户怎么用** | 控制台「实时监控」区：看内嵌浏览器实时画面 + 一个明显的红点光标，跟随机器鼠标移动/滚动/点击；下方实时日志逐行打印引擎动作。 |
| **详细规则** | ① 画面用 CDP 截图流（screencast）实时推送。② 红点 = 机器鼠标位置：移动按贝塞尔轨迹、滚动随页翻动、点击放一圈扩散环；走过留**淡出的彗星尾巴**画出路径。③ 监控画面一连上，红点**居中常驻显示**（带呼吸脉动），便于辨认。④ 画面可点击 = 直接在监控里操作内嵌浏览器；坐标按画面缩放比映射。 |
| **输入 / 输出** | 输入：引擎动作坐标流（move/scroll/click）。输出：实时画面 + 红点轨迹 + 日志。 |
| **异常与边界** | 监控画面未连上（无截图帧）时红点不显示——属预期，连上即居中出现。 |
| **优先级** | P1 |
| **关联需求** | `FR-C`（可视化/可观测）· 反检测清单第 6 类 |

### 验收标准

- 跑检索时，红点沿轨迹移动、滚动翻页拖尾巴、点开笔记放扩散环。
- 红点足够明显（约 42px + 红心白环红晕 + 脉动），白底页面上清晰可见。
- 在监控画面上点击能驱动内嵌浏览器。

### 界面要点（mockup 见 HTML 版）

- 控制台：实时监控器（画面 + 红点轨迹）与实时日志并排；红点 42px、红心白环红晕、呼吸脉动。

## 2.13 评论承接：收件箱 + 自动回复 `[P0]` ○待实现

> 对外评论是"主动出击"，承接是"接住回头客"。别人**评论了我的笔记 / 回复了我的留言 / @我** → 自动接住、按意向回复、沉淀线索。承接回复**优先级高于主动评论**：任务运行中随时发现有通知，先回复再回外呼。

### 功能卡

| 字段 | 内容 |
|---|---|
| **功能目的** | 补上获客闭环后半段：接住已经在跟你互动的人（意向远高于冷启动），自动回复并沉淀为线索。 |
| **用户怎么用** | 与主动评论同一个「开始」：引擎边外呼边盯通知，发现「评论和@」有新内容就暂停外呼、进通知页逐条回复、再回外呼。回复内容/状态在「线索·承接」页看，规则在「评论承接」设置页配。 |
| **详细规则** | ① **抢占式单循环**：每个安全断点（评完/关掉一篇笔记、回到列表时）先**读底部「通知」红点**（纯读 DOM、不动鼠标、零打扰）；有未读 → 暂停外呼 → 进通知页 → 抓「评论和@」→ 逐条判意向+回复 → 回搜索页继续。② 检查只"看"不点；确有未读才点进去。③ 回复**永远第一优先级**，外呼填空闲。④ 不掐在输入/发送中间，只在断点切换。⑤ 回复走 JS 合成事件 + 红点慢动作可见（同评论/筛选）。⑥ 一轮最多回 M 条就还控制权给外呼（防饿死）。⑦ 红线：回复**不留明文微信/电话/二维码/外链**，一律"看主页/私聊"。 |
| **输入 / 输出** | 输入：通知页「评论和@」条目（昵称/内容/笔记/动作/日期/主页链接）。输出：自动回复 + inbox 记录 + 高意向线索。 |
| **异常与边界** | 笔记详情页底栏不在 → 放到"回到列表"断点读红点；读不到则每 N 分钟轻进通知页看一眼。回复没定位到框/发送没确认 → 标 failed、不算已回、下轮可重试（有上限）。连续失败/登录掉线/风控提示 → 安全刹车自动停。 |
| **优先级** | P0 |
| **关联需求** | 承接/转化 · 反检测清单第 4 类（安全刹车）· 私信一期方案（同源承接思路） |

### 执行策略（抢占循环）

```
任务开始 → 循环：
  ① 该停吗？(停止 / 安全刹车 / 不在排班时段) → 是则结束
  ② 看通知红点（读 DOM，不动鼠标）
       有未读 → 暂停外呼 → 进通知页 → 抓「评论和@」
              → 逐条：判意向 → 命中规则才回 → 生成回复 → 限频闸门 → 回复(演练/真发) → 记录
              → 一轮≤M条 → 回搜索页
  ③ 没未读 / 已处理完 → 外呼走一步（下一篇求租帖 → 浏览 → 评论）
  ④ 回到 ①
```

- 顺序：高意向优先 → 再新→旧。节奏：每条回复隔 `reply_gap`（拟人）；检查通知频率可配（每篇 / 每滚几下 / 兜底 N 分钟）。
- 演练 vs 真发：演练只定位+生成草稿不发；真发才发（二次确认、用全新小号）。
- 单浏览器 = 单循环抢占，不是两个真并行线程；效果上回复随时插队、处理完回到外呼上下文（靠去重恢复，不依赖滚动位置）。

### 配置项（「评论承接」设置页，全部可配、不写死）

| 配置 | 默认 | 说明 |
|---|---|---|
| 承接范围 | 回我评论✓ / 评我笔记✓ / 赞收藏✗ / 关注✗ | 勾选要接的动作；可开"自动回关" |
| 意向关键词 | 求租/多少钱/有房吗/还在吗/怎么联系… | 命中才回；可增减 |
| 黑名单/黑词 | 中介/同行/广告… | 命中跳过；已回过的不重复回 |
| 只回复近 N 天 | 7（0=不限） | 只接近 N 天的评论；抓取时滚到更老就停，不用把历史全读一遍 |
| 回复话术 | 分意向多套、轮换 | 模板/AI 切换（接 LLM）；红线不留联系方式 |
| 回复限频 | 日上限/每小时/最小间隔 | 可共用评论限频或单独配 `reply_*` |
| 一轮上限 M | 5 | 一次承接最多回几条，防外呼饿死 |
| 检查通知频率 | 每篇 + 兜底 5 分钟 | 多久"看"一次红点 |
| 真发开关 | 关（演练） | 勾选真发，二次确认 |

### 结果记录

- **inbox 收件箱**（每条）：昵称、主页链接、内容、对应笔记、动作类型、意向、**状态**（待处理/已回复/跳过/失败/演练）、回复内容、失败原因、时间。
- **实时日志** + 落库：引擎逐行打印（发现通知→进通知页→回复某人→成功/失败）。
- **统计**：今日收到/已回/跳过/失败/高意向、回复成功率（喂安全刹车）。
- **线索沉淀**（leads 扩展）：高意向 → 昵称/主页/最近诉求/**跟进状态**（待跟进/已加微/转人工/无效），可看完整往来。

### 数据模型（新增/扩展）

- `inbox`：id, type, nick, user_link, content, note_title, note_url, action_date, intent, status, reply_text, fail_reason, received_at, replied_at, dedup_key
- `leads`（扩展）：id, nick, user_link, last_intent, last_content, stage, note_url, created_at, updated_at

### 验收标准

- 任务运行中制造一条新评论通知 → 引擎在下一个断点"看"到红点 → 暂停外呼 → 进通知页回复该人 → 回外呼。
- 检查通知不移动鼠标、不打断外呼（纯读 DOM）。
- 回复按意向、不雷同、无明文联系方式。
- 「线索·承接」页能看到这条收件 + 状态 + 回复；高意向进线索。
- 演练只生成不发；真发受限频 + 安全刹车。

### 界面要点（mockup 见 HTML 版）

### 分步实现（边做边改）

1. **抓取+展示** — inbox 表 + `scanInbox` + 「线索·承接」页只读展示 + 统计。
2. **规则+意向** — 「评论承接」设置页 + 意向判定（范围/意向词/黑词）。
3. **回复+执行策略** — 抢占循环（看红点→插队回复→回外呼）+ 回复(演练→真发) + 限频/刹车/失败重试 + 结果落库。
4. **线索沉淀** — 高意向进 leads + 跟进状态 + 往来追溯 + 挂排班自动收回。
