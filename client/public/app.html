✓ 外呼对象：仅处理已确认在服务区域内的“租户/求租者”笔记。先评论该笔记作者；再仅在这类求租笔记的评论区，回复明确求租的人。房东、转租方、房源发布者和同行/中介笔记会整篇跳过。

📅 排班 · 时间段「每个关键词采集多少篇 / 共评多少条」
默认每个时间段每天生效。需要错峰时,新增多个时间段;需要区分工作日/周末时,在该时间段里勾选适用星期。“每词采集”由你直接设置，不再由系统平均分配。例如 5 个关键词、每词采集 50 篇，一轮最多采集 250 篇；“评”仍是整个时间段的评论总配额。
🧭 获客模型 · 笔记分类规则
这里定义“什么样的笔记值得处理”。采集会按这些分类区分笔记,动作=评论的分类会进入待评论队列。租房只是默认模板,可以改成教育、装修、二手车等行业。
无论开关状态，每篇笔记都会先打开并读取标题＋完整正文。关闭时按下面的命中/排除关键词分类；打开时按每个分类的“LLM 判断说明”分类。模型服务商和 API Key 在“模型设置”中配置。
填写实际有房源、愿意承接的区域，尽量写到行政区、商圈、地铁站或村/小区。关闭大模型时按标题＋正文的关键词/区域规则判断；开启大模型时把正文提取的地点和这些服务区域交给模型做地理诊断。明确在服务区外的笔记会整篇跳过。
